# Usage, adoption and reliability dashboard prototype

`dashboards/usage.json` is a stock Grafana dashboard; no third-party plugin is needed. This is a synthetic read model, not production telemetry or a released QaaS feature. It uses one terminal observation per attempt and an **independent** eligible/enrolled project roster and mature expected-attempt ledger. The JSON is generated by `make_dashboard.py`.

## Reproduce

Run in this directory with Python 3.11+ and SQLite (including its standard JSON functions):

```sh
python tests.py
python make_dashboard.py
python serve.py --print > evidence/metrics.prom
python oracle.py evidence/metrics.prom > evidence/oracle.json

# From a Linux environment supporting private user/network namespaces:
unshare --user --map-root-user --net python grafana/offline_loopback.py \
  python grafana/smoke_api.py \
  --grafana-home /path/to/grafana-12.3.0 \
  --prometheus /path/to/prometheus-3.5.1/prometheus
```

The runtime verifier starts and removes its own temporary backend stores. It binds exporter, Prometheus, and Grafana to loopback (ports 19332, 19090 and 13000). The isolation helper refuses to alter an existing network or use any namespace with a non-loopback interface. No real credentials, SUT, traffic or exporters are used. It imports the JSON under UID `qaas-usage-budget` and tests all panel/scope cells against the SQLite oracle through both Grafana's datasource proxy and its native data-frame API. No open process is required after the run. Optional `--screenshot` requires local Playwright and Chromium and only opens the disposable local server.

To import manually, configure a Prometheus datasource with UID `qaas-prometheus`, scrape `127.0.0.1:19332/metrics` as job `qaas_kpi` (sample config provided), then import the JSON. A companion pipeline dashboard links via UID `qaas-operations-budget` when also imported. Use one logical scrape target, or independently deduplicate replicas before using these already precomputed gauges. Do not aggregate an “all” series with its component scopes or average gauge ratios/percentiles across scopes.

Versions used, matched to official published SHA-256:

- [Grafana OSS 12.3.0](https://dl.grafana.com/oss/release/grafana-12.3.0.linux-amd64.tar.gz): `dd34d03f8dbf815f153b638b793e6ab1b9d205b7c0a15dddd851332f0c9ac01c`.
- [Prometheus 3.5.1](https://github.com/prometheus/prometheus/releases/download/v3.5.1/prometheus-3.5.1.linux-amd64.tar.gz): `cd6aea0ab214b05838470668dfcee7d01a7d91913509a227b00401ca872423f0`.

## Interpretation

- Windows are exactly `[cutoff − days × 86400 seconds, cutoff)` in UTC. The business cutoff is fixed by the fixture, not the Grafana time picker. Applicable project team and environment are from the roster as of cutoff. Projects not eligible at cutoff and observations before eligibility started are outside both numerator and denominator. This does not reconstruct historical roster transitions.
- Adoption means **observed use**: distinct current eligible projects with a terminal attempt, including cancellations, divided by independently rostered current eligible projects. Enrollment is shown separately. A retry with a new canonical attempt ID counts as another attempt, never as another project. A missing terminal is not evidence that the project was inactive.
- Throughput is **terminal attempts/day**, including cancelled and unexpected observations. Capability counts are **attempts** using Run, Act or Assert at least once; categories overlap. They are neither per-hook counts nor personal behavior analytics.
- Functional failure is assertion failure ÷ (passes + assertion failures). Observed infrastructure failure is infrastructure failure ÷ (passes + assertion failures + infrastructure failures). These are not one interchangeable “failure rate.”
- Platform goodness is matched valid terminal outcomes (pass or assertion failure) ÷ mature independently expected attempts. Missing records, observed infrastructure errors, and cancellation don't count as good. This fixture has no independent confirmed-cancellation exclusion policy.
- Coverage requires same project and attempt ID with **both** expected due timestamp and observed terminal timestamp in the same selected window. A due item with a completion outside that window is missing for that window, not evidence that it never completed. Unexpected observations never increase coverage even if numerator/denominator coincidentally match.
- p50/p95 use exact nearest rank over durations from pass, assertion failure and infrastructure failure, in seconds. No cancellation. The duration/infra denominator is displayed.
- No eligible roster/expected observations/evaluable samples means an undefined ratio or duration. It emits no series for that cell (Grafana can show “No data”). Defined zero remains zero. A cancelled attempt can contribute to collection coverage while leaving reliability, failure denominators, or duration metrics different.

| Synthetic all-team/all-environment result | 7 days | 30 days |
| --- | ---: | ---: |
| Adoption | 3/5 | 4/5 |
| Enrolled | 4 | 4 |
| Terminal attempts (runs/day) | 7 (1) | 10 (0.333) |
| Run / Act / Assert | 7 / 5 / 4 | 10 / 8 / 7 |
| Functional failure | 1/4 | 2/7 |
| Observed infrastructure failure | 2/6 | 2/9 |
| Platform good / expected | 4/7 | 7/10 |
| Expected covered | 6/7 | 9/10 |
| Missing / unexpected | 1 / 1 | 1 / 1 |
| Durations p50 / p95 | 3 s / 11 s | 3 s / 11 s |

The payments × staging selection has no denominator. Seven- and 30-day boundary cases, a repeat project with distinct attempts, independent expected-but-missing data, an unexpected terminal, cancellation, offboarding and pre-eligibility samples are built into the fixture. Duplicate canonical IDs and incompatible scopes fail closed. Separate exact scope gauges cap application cardinality at **29 metric families × 18 allowlisted scopes = 522** per logical target; the fixture emits **502** with undefined cells omitted. No project IDs, run IDs, arbitrary scope, exception messages, or URLs are metric labels. Prometheus adds job/instance labels. This is not a streaming ingestion or historical trend implementation.
